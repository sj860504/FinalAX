# 상대 영역 문제를 이슈로 넘기기

CLAUDE.md 1항: 상대 소유 폴더는 읽기만 하고, 수정이 필요하면 `[요청]`/`[블로커]` 이슈를 만들어 어싸인한다. 이 스킬은 그 이슈를 **재현 가능한 형태로** 만드는 절차다.

## 0. 입력
사용자 설명 `$ARGUMENTS`. 비어 있으면 대화 맥락에서 문제를 찾고, 없으면 한 번만 묻는다: "무슨 화면/호출에서 뭐가 기대와 달랐나요?"

## 1. 사실 수집 (추측 금지)
아래를 **실제로 실행해서** 채운다. 못 채운 항목은 "확인 못 함"으로 남긴다.
- **엔드포인트**: `shared/api-contract.md`에서 해당 API 항목을 찾아 계약상 요청/응답을 인용한다.
- **실제 응답**: 백엔드가 떠 있으면 `curl -s -i http://localhost:8000/<path>` 로 상태 코드·본문을 직접 받는다. 안 떠 있으면 프론트 콘솔/네트워크 로그에서 가져온다.
- **재현 절차**: 화면 기준 2~4단계, 또는 curl 한 줄.
- **영향**: `docs/demo/scenario.md`의 어느 단계가 막히는지. 데모 필수면 `P1`.
- **우회 여부**: `VITE_USE_MOCK=true` 로 진행 가능한지.

## 2. 담당자·라벨 결정
CLAUDE.md 1항 표에서 문제가 난 폴더의 소유자를 어싸인한다 (`backend/`·`data/` → 백엔드 담당, `frontend/` → 프론트 담당, `shared/` → 둘 다 멘션). 담당자 GitHub ID가 표에 `@팀원ID`로 남아 있으면 사용자에게 실제 ID를 묻는다.
- 내가 지금 막혀서 진행 불가 → 제목 `[블로커] …`, 라벨 `blocker`
- 진행은 되지만 고쳐야 함 → 제목 `[요청] …`, 라벨 `request`
- 영역 라벨(`backend`/`frontend`/`shared`) + 우선순위(`P1`/`P2`) 추가

## 3. 중복 확인
```
gh issue list --state open --label <영역> --search "<핵심 키워드>"
```
비슷한 이슈가 있으면 새로 만들지 말고 그 이슈에 코멘트로 추가 정보를 남기는 쪽을 제안한다.

## 4. 초안 보여주고 등록
`templates/request.md` 형식으로 본문을 만들어 **먼저 사용자에게 보여준다**. 확인 후:
```
gh issue create --title "<제목>" --label <라벨들> --assignee <담당자> --body-file <초안파일>
```
초안 파일은 스크래치패드에 쓴다. 생성된 이슈 URL을 알려준다.

## 5. 마무리
- 내가 이 이슈 때문에 막혀 있으면, 우회 방법(mock 전환)을 실행해 내 작업을 계속한다 (CLAUDE.md 7항 "막혔을 때").
- 상대 폴더 파일은 **절대 수정하지 않는다.** "이렇게 고치면 될 것 같다"는 제안은 이슈 본문의 "추정 원인" 칸에만 쓴다.
